[[The task||任务定义]]

[[The task covers 100 biomedical papers in PMC JATS XML format.||任务包含 100 篇生物医学论文，输入为 PMC JATS XML 全文。]]

[[Task 1 · Gene and disease extraction||任务 1 · 基因与疾病实体抽取]]

[[Extract all gene and disease mentions from each paper and output the identified entity lists, if any.||抽取每篇论文中提及的所有基因与疾病名称，并输出识别出的实体列表（如有）。]]

[[Task 2 · Gene–disease relationship analysis||任务 2 · 基因–疾病关系分析]]

[[For paper i with Ni genes and Mi diseases, evaluate all Ni × Mi candidate pairs. Link a pair if the paper provides evidence of an association, correlation, or causal relationship, yielding a gene–disease bipartite graph per paper.||对含 Ni 个基因与 Mi 个疾病的第 i 篇论文，评估全部 Ni × Mi 个候选配对；若原文提供关联、相关或因果关系的证据则建立连边，最终构建每篇论文的基因–疾病二部图。]]

[[We also record whether a relation is a finding of the paper or background knowledge. Pairs with weak evidence are marked uncertain and kept separate from the supported links.||在原任务之外，我们还标注关系来自本文发现还是背景知识。证据不足的配对记为 uncertain，与 supported 连边分开。]]

[[How the rules were developed||规则是怎样确定的]]

[[We used PubTator3 as a baseline. Early blind tests included Claude Opus 5.5, GPT-6.1 Sol and GPT-6 Astra.||对比基线为 PubTator3。早期盲测使用了 Claude Opus 5.5、GPT-6.1 Sol 和 GPT-6 Astra。]]

1[[Write the rules||编写规则]]

[[Write the extraction steps and decision rules in skill.md.||在 skill.md 中写明抽取步骤和判定规则。]]

2[[Try pilot papers||试跑论文]]

[[Refine the rules on pilot papers, then fix the evaluation sets before comparing configurations.||用试点论文修改规则，在比较配置前固定评估集。]]

3[[Blind test||独立盲测]]

[[Run the papers in fresh sessions using only the written rules.||在新会话中运行论文，只提供书面规则。]]

4[[Format verification||格式校验]]

[[Check quotes, character offsets and output tables with local code.||用本地代码检查引文、字符偏移和输出表格。]]

5[[Result table||结果对比表]]

[[Compare model outputs and rule versions for each gene–disease pair.||逐对比较模型输出和规则版本。]]

[[Use disagreements to revise the rules or add boundary cases for the next round.||将分歧补入规则或边界案例，留待下一轮测试。]]

[[From full rules to a decision card||从完整规则到判定卡]]

  • [[We reviewed existing systems and chose PubTator3 for comparison.||调研现有系统后，我们选择 PubTator3 做对比。]]
  • [[We developed the rules on 5 pilot papers, from Skill 1.0 to 1.3, and collected 35 boundary cases to check consistency.||规则在 5 篇试点论文上从 Skill 1.0 修改到 1.3，另整理了 35 个边界案例检查判定是否一致。]]
  • [[We shortened the rules into a decision card to reduce input tokens and interaction turns. It agreed with the full rules on 110/112 boundary-case decisions, with the same result across 3 runs.||为减少输入 token 和交互轮次，我们把完整规则压缩成判定卡。在边界案例测试中，110/112 个判定与完整规则相同，3 次运行结果一致。]]
  • [[We compared the rule and reasoning configurations on a fixed set of 12 papers.||随后在固定的 12 篇论文上比较规则和推理配置。]]
  • [[We used the selected V1 configuration for all 100 papers, then evaluated it on BioRED without BioRED-specific training or prompt tuning.||选定 V1 后，运行全部 100 篇论文，再用 BioRED 评估；没有针对 BioRED 做训练或提示词调优。]]

[[Cost and runtime||成本与耗时]]

[[These runs used Claude Opus 5.5. Costs are the CLI-reported list prices and include repair requests.||以下运行使用 Claude Opus 5.5，成本按 CLI 报告的官方标价统计，包含修复请求。]]

[[The paper sets differ between rows. The 100-paper average includes long papers and all repair requests.||各行使用的论文集不同。100 篇均值包含长论文和全部修复请求。]]

[[Reducing model calls||减少模型调用]]

  • [[We checked model behavior on 5 baseline papers before and after each change.||每次修改前后，都在 5 篇基准论文上检查模型行为。]]
  • [[Local code locates text spans and calculates character offsets.||文本定位和字符偏移计算交给本地代码。]]
  • [[Each paper gets one initial request and, if validation fails, at most one repair request.||每篇论文先请求一次；校验失败时，至多再请求一次修复。]]
  • [[The shorter rules reduced input from 20k to 9k tokens and are reused as a cached system prompt.||压缩规则后，输入从 20k 降到 9k tokens，并通过缓存系统提示词复用。]]

[[Shorter model responses||缩短模型输出]]

  • [[The response contains entities, evidence references and gene–disease pairs.||模型返回实体、证据引用和基因–疾病配对。]]
  • [[The model returns sentence numbers. Local code then retrieves the original quotes and their character offsets.||模型只返回句子编号，本地代码再取出原文并计算字符偏移。]]
  • [[Very long documents, such as conference proceedings, are split into chunks.||会议论文集等超长文献分块处理。]]

[[Extraction steps||抽取步骤]]

1[[Prepare the prompt||准备输入]]

[[Put the rules, numbered paragraphs and sentences, and response schema in one prompt.||将规则、编号后的段落和句子、输出格式放入同一条提示词。]]

2[[Run the model||模型抽取]]

[[Return structured judgments without tool calls, file reads or shell commands.||模型直接返回结构化判定，不调用工具、读文件或执行命令。]]

3[[Recover source spans||回填原文]]

[[Locate mentions, calculate offsets, fill the gene × disease matrix and check the output format.||本地代码定位实体提及、计算偏移、补全基因 × 疾病矩阵，并检查格式。]]

4[[Repair if needed||按需修复]]

[[Send validation errors, such as a mismatched citation, back to the model for one repair attempt.||如有引文不匹配等校验错误，将错误发回模型，尝试修复一次。]]

  • [[Our output contains 2.8 times as many relation pairs (64 vs 23), each with source sentences. These counts alone do not measure accuracy or recall.||本方法报告的关系对数量为基线的 2.8 倍（64 vs 23），每条附原文句子。仅凭这些数量，无法判断准确率或召回率。]]

  • [[Distinguishes clinical symptoms from formal disease entities.||将临床症状与正式的疾病实体区分开。]]
  • [[The method returned relations from a Spanish paper for which PubTator3 returned no genes.||在一篇西班牙语论文中，本方法抽取到了关系，PubTator3 未返回基因。]]

[[Limitations||局限性]]

  • [[For these 12 papers, the mean was $0.38 and 70 s per paper including repairs ($0.30 for the first request). PubTator3 annotations are free to query.||这 12 篇论文平均每篇花费 $0.38、耗时 70 秒，包含修复；仅首次请求为 $0.30。PubTator3 的预计算标注可免费查询。]]
  • [[Our supported set excludes 12 pairs reported by PubTator3: 3 involve entities our rules classify as symptoms, 4 received non-supported labels, and 5 involve an entity we did not capture. The disagreements await independent review.||我们的 supported 集合未包含 PubTator3 报告的 12 对：3 对涉及本规则归为症状的实体，4 对未判为 supported，5 对涉及未捕获的实体。这些分歧尚未经过独立复核。]]
  • [[Does not normalize entities to database identifiers (NCBI Gene / MeSH).||暂未将实体标准化映射至数据库标识符（NCBI Gene / MeSH）。]]
