# 1.3.0 边界案例与后续试点

[boundary-cases.json](boundary-cases.json)收录35个规则回归案例，新增BC31–BC35；预期在后续模型运行前固定。paper_excerpt明确记录原文片段、位置和输入哈希；synthetic明确为人为构造，G/H/D等只是符号，不是生物医学事实。案例的片段任务不等于整篇论文答案，也不是医学金标准。旧BC09/BC22/BC23仅将expected字段conflict_impact规范为impact，不改变对应预期值；旧版本案例保留在Git历史。

覆盖：背景病因无需重述全部实验、带支持结果的suggested、只确认检出的confirmed、报道动词转述阴性、ZPLD1的未解决语境、两种身份未知情形、混合来源、同问题冲突/不同问题不冲突、集合/联合效应、总体阴性、显著负相关、未读统计量、构建体物种、同家族与笔误、跨研究单元、数值矛盾、远距离回指、临床事件、层级、非英文引文和仅研究目的。

几个关键对照：

|案例|规则行为|
|---|---|

|BC11 / BC12 / BC13|复合物、联合干预、集合机制分别核查，不用一个模板分配所有成员/亚型。|

|BC32|唯一关系线索为预设时uncertain/presupposed_only，附命名成员上下文，不能跳过指代核对。|
|BC33 / BC35|宽泛疾病类别正常纳入；纯表头分组标签不增主节点，保留下级条目。|
|BC34|无引用编号的明确既有知识标背景并记录citation_absent，不编造引用。|

## 结构/引文检查与输入导出

包内脚本仅用Python标准库；不会调用模型、改案例预期或重跑论文：

```powershell
python scripts/validate_cases.py
python scripts/validate_cases.py --source-xml PATH_TO_PMC10014009.xml
python scripts/validate_cases.py --export-prompts PATH_TO_PROMPTS.json
```

以上相对路径从本Skill目录执行。结构检查涵盖ID、规则引用、枚举、链接、真实/合成来源区分；提供原XML时还检查输入哈希与规范化引文存在性。脚本不重新构建项目解析器的b编号；原文案例的b位置在发布时另用项目JATS解析器核对。未提供XML时报告未核查引文数，不能说引文全通过。

导出的prompts删除expected/rationale，便于后续模型运行；这些字段仍在案例源文件中。测试运行若已读取答案或本案例说明，不得称盲法。哈希应在测试开始前记录，完成后保留模型原输出和逐项裁决。程序检查通过不等于模型已按规则做对；本次1.3.0发布没有运行新的独立模型行为测试。第一篇1.2.0的外部试点反馈是修订输入，不等于本次发布对其盲法或语义结论作独立验证。
